## 加载比较

同一台 Apple M1 Pro、同版本 Chrome，Playwright 无界面模式，1200 × 910 CSS 像素、设备像素比 2。新旧版本分别从本地 HTTP 服务加载，关闭浏览器缓存，模拟每秒 1,500,000 字节下载带宽和 150 ms 网络延迟。先等首页街市预热完成，再计时点击「穿越」到「启程」可用。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首次可操作 | 13,820 ms | 5,173 ms |
| 四张运行图 | 10,900,581 字节 | 2,718,448 字节 |
| 图片请求开始 | 世界、河水、庭院、人物串行 | 四张图均在点击后约 794 ms 开始 |
| 人物桌面颗粒 | 160000 | 80000 |
| 人物窄屏颗粒 | 60000 | 24000 |
| 全屏柔光邻域采样 | 49 | 9 |

此次限速条件下可操作时间减少约 63%，四张图体积减少约 75%。优化后的虹桥不等待人物图下载结束：可操作时刻约 5.17 秒，人物图下载结束约 5.54 秒。以上为模拟网络的单次测量，不能视为所有真实网络的固定加载时间。

桌面短时采样中两版都接近无界面浏览器约 60 FPS 的上限，没有据此声称帧率翻倍。优化减少的是每帧资源负担，并通过动态分辨率缓解低性能设备上的持续慢帧；尚未在实体手机上测帧率。

## 实现

`crossing-quality.js` 设置初始像素与颗粒预算，并在持续慢帧时降低内部渲染分辨率。`crossing-three.js` 并行准备世界、河水和庭院，第一幕先返回可用控制器；庭院完全遮盖后跳过世界、倒影与水面绘制，倒退时恢复。`crossing-courtyard.js` 并行加载背景和人物；人物实例准备分片让出主线程，以便处理返回操作。隐藏后的数字覆盖层只清空一次。

原始 PNG 和项目夏景素材继续保留；穿越只请求新的运行 WebP。人物无损，背景为高质量有损压缩，颗粒密度与内部清晰度按性能预算调整。
