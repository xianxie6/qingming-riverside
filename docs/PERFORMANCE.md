# 性能优化验证

## 2026-09-23 第二轮：高像素密度下的城门与灯会

这轮针对新增灯会后的卡顿。保留源素材、人物数量和动作网格，不锁低帧率。

- 城门灯笼、兔灯和手持灯笼的滤镜结果改为高密度小画布缓存；只在光照档位改变时更新，并只保留当前版本，避免逐帧处理大图。
- 舞者网格先绘制到各自的小画布，再合成一次；原有顶点和动作保持一致。酒楼、等位游客和舞者中完全仿射的网格单元合为一次采样，非仿射单元仍保留两个三角形。
- 人物中间画布按实际显示像素密度采样，缩放或切换场景时正确重建居民缓存；最终画布像素密度不变。
- 水面/瀑布通过 GPU 裁剪与局部合成限制绘制范围；看不到水面时跳过该通道。水面纹理只上传河流和位移余量，保持原像素密度，减少移动镜头时的纹理传输。
- 酒楼坐标转换复用窗口尺寸，避免每个人物每帧重复读取布局。镜头接近目标时收敛到目标值，停止无意义的背景失效。

同一 Chromium、1440 × 900、DPR 2，关闭测量外的动态页面，分别加载本轮开始前快照和修改后代码。每个场景采样 3 秒，夜景等过渡完全结束再采样：

| 场景 | 修复前 FPS | 修复后 FPS | P95 帧间隔变化 |
| --- | ---: | ---: | ---: |
| 茶市静止镜头 | 120.0 | 120.0 | 8.6 → 9.0 ms |
| 城门 | 35.7 | 120.0 | 34.0 → 9.1 ms |
| 中秋街市 | 27.6 | 91.1 | 41.1 → 17.0 ms |
| 月下舞台 | 26.7 | 87.4 | 43.1 → 17.4 ms |
| 中秋夜景 | 16.9 | 97.7 | 66.8 → 16.8 ms |

这些是本机短时采样，不代表所有设备帧率。以上测量在最终河流纹理裁剪前完成；最后一次移动镜头与交互验证另记在 `output/playwright/repair-final-check.txt`。完整对比脚本与原始数据在 `output/playwright/repair-comparison.cjs` 和 `repair-comparison.txt`。

最终交互检查：手机模拟 390 × 844、DPR 2 的灯会为 120 FPS；酒楼入店、入席、点餐、上菜和等位游客流程为 120 FPS。返回灯会外街市、放大、触发时雨和水磨瀑布显示通过，无脚本异常。酒楼入店与席位使用 DOM 事件触发，未验证这两个入口的鼠标命中位置。最后一轮移动镜头样本为 79.8 → 71.5 FPS，P95 均为 17.6 ms，未证实该场景提速；本轮提升主要集中在城门和灯会。

验证：81 项 Node 测试通过，新增像素密度变化缓存失效、仿射/非仿射网格分支、水面范围裁剪与不可见时跳过上传检查。`npm run check` 静态构建与 Cloudflare dry-run 通过，未发布。

## 改动

- 主街市：人物画布尺寸统一向上取整，再判断是否需要重新分配，消除小数缩放/像素密度造成的逐帧重建。背景按原设备像素缓存，镜头、缩放、窗口、街区素材或地面湿度改变时重新绘制；水面使用同一张背景缓存。
- 中秋街市：动态画布仅覆盖当前视窗，以原像素密度绘制；屏幕外的角色仍推进动作时间，进入视野再绘制。跳过屏幕外的舞者、兔灯和彩球绘制。布局尺寸在 ResizeObserver 中更新，避免每个人物重复读取布局。显示弹窗时停止主街市绘制。
- 加载：舞者、兔灯、坐姿画师与节日天空在进入中秋街市时加载，原文件与清晰度不变；所有素材就绪后显示街市。节日天空、月亮、舞台的预处理结果复用。
- 酒楼：食客画布仅在实际尺寸改变时重建，每帧显式清空并重置变换；伙计、画师和节日舞者的同一个网格顶点每帧只计算一次，网格数量与计算公式不变。后台标签页跳过食客绘制。

## 本机浏览器对比

同一 Chromium 浏览器，1440 × 900，DPR 1，依次加载工作开始前的文件快照与优化后文件。进入茶市预热 2 秒后采样 4 秒，打开中秋街市并预热后再次采样 4 秒。测量使用 requestAnimationFrame 的实际间隔，没有限制动画帧率。

| 场景 | 优化前平均 FPS | 优化后平均 FPS | 优化前 P95 帧间隔 | 优化后 P95 帧间隔 |
| --- | ---: | ---: | ---: | ---: |
| 沿河茶市 | 29.2 | 50.8 | 57.6 ms | 55.9 ms |
| 中秋街市 | 20.4 | 47.0 | 76.6 ms | 54.6 ms |

此窗口下，中秋动态画布由 2058 × 686 缩为可见区域的 1440 × 686，节省约 30% 的像素处理量；只是裁去屏幕外区域，没有缩小可见人物或降低采样密度。帧率受设备、浏览器、视窗和角色动作阶段影响，仍存在慢帧，不代表所有设备稳定达到 60 FPS。
