# 穿越入口线上性能检查（2026-10-10）

检查网址：https://xianxie6.github.io/qingming-riverside/ 。本次只检查与记录，没有修改运行代码或发布。

## 实测结果

浏览器为 Playwright 启动的有界面 Chromium，Apple M1 Pro / ANGLE Metal，1200 × 910 CSS 像素，设备像素比 2。首页街市资源已经预热完成，再点击「穿越」，计时到「启程」按钮可用。网络为本机当时实际网络，未模拟限速。

| 项目 | 结果 |
| --- | --- |
| 首次打开，第一轮 | 15,999 ms |
| 首次打开，新浏览器第二轮 | 11,052 ms |
| 第二轮同页退出后重新打开 | 435 ms |
| 桥梁阶段，3 秒 rAF 采样 | 118 FPS；p95 帧间隔 9.1 ms |
| 庭院人物阶段，停留 3 秒后采样 3 秒 | 92 FPS；p95 帧间隔 17.1 ms |
| 第一轮进入期间超过 100 ms 的主线程长任务 | 1 次，430 ms |

帧率来自浏览器 rAF 回调间隔，不是 GPU 计时；强性能桌面上的短时结果不能代表手机或低性能设备。此次明显复现的是首次进入等待，本机未复现持续严重卡顿。两轮首次时间受网络变化影响，不能当作所有用户的固定时间。

## 确认的加载瓶颈

入口点击才请求三维模块，模块又分层请求依赖。随后 `createCrossing` 依次等待世界、河水、庭院；庭院内部等待背景后才请求人物图。第一幕必须等第二幕所有资源及人物实例构建完成后，才开始显示并开放「启程」。

第二轮资源时序（相对页面 navigation start；入口点击约 11.1 秒）：

| 资源 | 请求开始 | 响应结束 | 响应体字节 |
| --- | --- | --- | --- |
| crossing-river-forward-v1.png | 15,109 ms | 17,427 ms | 2,793,559 |
| seasons/summer-east.png | 17,487 ms | 19,325 ms | 3,019,249 |
| crossing-courtyard-painted-v2.png | 19,328 ms | 20,951 ms | 2,979,754 |
| crossing-painter-v2.png | 20,952 ms | 22,087 ms | 2,108,019 |

四张图合计 10,900,581 字节，约 10.9 MB。这四段下载基本串行，第二轮合计等待约 7 秒；模块依赖的请求瀑布另占数秒。缓存后同页重进约 0.44 秒，进一步支持首次下载是主要瓶颈。音乐文件本地约 5.5 MB，点击同时开始播放，但没有证据表明它阻塞按钮可用，未将其计入上述四张图。

## 运行阶段的额外负担

- 桌面人物为 160,000 个实例球体，窄屏为 60,000 个；顶点着色器对每个球体顶点执行散聚、旋转扰动和鼠标影响计算。
- 桌面渲染像素比上限 1.65，比像素比 1 多约 2.72 倍像素；庭院阶段还对每个输出像素进行 49 次邻域采样来添加柔光。
- 庭院完全遮住河道后，桥、水面、倒影仍然绘制；倒影每两帧一次，阴影每三帧更新。
- 首页烟花已通过 `crossing-active` 暂停；街市场景在 `in-atlas` 状态跳过绘制。此次没有发现首页动画持续绘制是主要原因。
- 访问计数的 Cloudflare API 在本机网络有连接失败或超时，属于非阻塞请求；没有证据将其视为穿越加载的主因。

## 建议处理顺序

1. 将穿越专用背景改为适合显示尺寸的 WebP，并为河水制作单独的小纹理；人物采样图保留透明度与颜色精度，转换后验证颗粒轮廓。
2. 并行发起独立资源请求，让第一幕先显示，第二幕按需准备；保留提前进入第二幕、退出、重进和加载失败的处理。
3. 庭院完全显示时停止河道、倒影和阴影绘制；返回第一幕时恢复。
4. 按设备性能调整颗粒数量与内部渲染尺寸，柔光改为低分辨率或两次可分离滤波；用同一设备、视口和网络条件验证收益与画面差异。
