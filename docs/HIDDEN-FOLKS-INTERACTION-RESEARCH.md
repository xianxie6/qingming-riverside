# Hidden Folks：可用于清明上河项目的交互与技术

调研日期：2026-10-15。范围：官方产品资料、开发者公开技术文章，以及本项目当前源码。此次只做研究，没有修改游戏功能。

## 判断

最值得借鉴的是“点一下，画中的生活发生一件小事”。建议先在续卷加入可操作的场景物件、角色主动回应、短因果链和分区声音，再把已有寻物收藏接进来。沿用现有 Canvas 2D 即可，当前没有证据支持为这些效果迁移引擎。

本报告的外部事实属于**公开文件确认**，本地功能属于**源码确认**，落地方案属于**设计建议**。未购买、安装或逐关实玩 Hidden Folks；未将官网宣传片或文案当作实操验证。部分外链动图未能通过本次浏览工具读取，因此没有对其逐帧表现作判断。

## 1. 可以确认的参考机制

| 机制 | 公开证据 | 对本项目的意义 |
| --- | --- | --- |
| 目标列表与线索 | 官方介绍：点目标获得线索，找到一定数量可进入下一区域 | 借鉴“观察—尝试—发现”的循环；续卷仍可自由浏览 |
| 物件可操作 | 官方举例包括打开帐篷、处理灌木、开关门和触碰动物 | 建筑和道具应承担交互，不能只把人物设为热点 |
| 手绘素材分层后编排动画 | 官方说明素材经过手绘、扫描、手动分层、动画与脚本编排 | 动画的基础是可独立操作的素材，而不是整幅图统一变形 |
| 无时间和分数压力 | 官方明确说明 | 探索失败可以只得到一个有趣回应，不必惩罚玩家 |

以上来源：[一代官方资料](https://hiddenfolks.com/press/hidden-folks-1)。

技术上，开发者公开描述了 Unity 中可组合的旋转、滑动、按钮脚本，组件通过数值或对象传递产生联动。声音设计则按地图位置组织环境声，并让缩放影响环境声，点击音效另作处理。这些是 2017 年开发文章公开的实现原则，不能由此确认当前全部内部代码、引擎版本或性能算法。[开发者 Factory 技术文章](https://store.steampowered.com/news/posts/?appids=435400&enddate=1497450198&feed=steam_community_announcements)

Unity 的使用另有[开发者 itch.io 产品页](https://adriaan.itch.io/hidden-folks)确认。官网是介绍与购买入口，其网页技术不能代表游戏渲染技术。

二代官方目前预告了“第二种非文字线索”，但未在文字资料中解释具体表现；本项目可据此探索图像提示，不应宣称某种圈选或高亮就是二代的实现。[二代官方资料](https://hiddenfolks.com/press/hidden-folks-2)

## 3. 优先落地的六类效果

这里的例子均为本项目的新设计建议，不代表 Hidden Folks 已有这些宋代场景。

### A. 场景物件能开、能拨、能拉——优先级最高

| 位置 | 用户动作 | 可见结果 | 素材与实现要求 |
| --- | --- | --- | --- |
| 客舍 | 点开布帘 | 布帘掀起，露出休息的旅客；再次点击放下 | 无布帘的干净底图、透明布帘、背后旅客；顶部转轴或少量形变 |
| 仓场 | 拖动吊绳 | 货物升起，搬运者接货 | 绳、吊钩、货包独立图层；受限滑动控制吊货进度 |
| 菜园 | 推开竹篱门 | 门扇打开，院内的小动物或人物露出 | 门后背景补绘、门扇独立、前后遮挡明确 |
| 茶摊 | 点击壶或桌边人物 | 完成一次提壶、倾倒、收壶 | 壶、手、杯盏有可用素材或关键姿态 |

门、帘、吊绳应先在小范围美术样板上验证。当前底图里已经画死的布帘或货物，必须先移除并补出后方内容；直接叠加一张可动图会留下原物件的影子。

### B. 人物被点后，临时切换成回应动作——低至中等工程成本

给现有角色增加 `idle → react → recover → idle` 状态，播放一次短动作后回到原活动。

- 农人：停一下手中劳作、抬头示意，再继续。
- 茶客：举杯回应；茶博士：完成一次添茶。
- 货郎：转向观看者、举起商品，再放下。

第一版可以使用现有网格表达点头、抬手和小幅俯身；涉及递出新物件、明显转身或完整挥臂时，需要拆件或补绘姿态。点击期间不要同时执行相冲突的工作循环。

相比统一增强晃动，这能让用户看懂“是我刚才点他，才发生了这个动作”。文字可在动作后短暂出现，反馈重点放在画面。

### C. 两至三个节点的生活机关——中等工程成本，效果突出

先做一个可反复体验的小故事：

> 拉动仓场吊绳 → 粮包升到台面 → 搬运者接货并放好 → 记账者落笔。

另一个候选是：开启渠闸 → 水流增强 → 水车转速改变 → 磨坊人物开始操作。水车旋转可评估复用主场景代码；闸门、水位和人物联动属于新增内容。

使用受控状态和时间线即可，不必先引入完整物理模拟。每一条链都要规定重复点击、半途打断、离开视野和返回时的行为，避免货物或人物卡在中间。

### D. 镜头移动时，声音逐渐换成这一带的生活——低至中等工程成本

续卷的横向结构很适合分区音景：田畴的鸟虫与劳作、茶市的杯盏与低声交谈、仓场的绳索与货物碰撞、柳岸的风水声。

建议使用三条音量通道：环境、交互、发现。环境按视口与区域的重叠程度混合，缩放时改变远近感；交互声音保持清晰。重要回应时短暂降低环境声属于本项目可采用的混音建议，不是已确认的 Hidden Folks 内部实现。

保持用户主动开启声音，隐藏页面时暂停。音源优先原创录制或合适的授权素材；沿用项目当前的声音开关。其独特拟声方式可作为创作启发，本项目更适合先做好木、布、水、杯盏等材质差异。

### E. 线索与收藏进续卷——复用已有逻辑，需重新绑定数据

为七个街区各选一至两个有动作特征的目标，用生活线索引导：例如“他每写一笔，都会再看一眼粮包”。目标可以藏在可打开的布帘后，形成“操作才发现”的小惊喜。

`collection.js` 已有提示、存档、收藏与特写，但采用旧地图的人物数据和视图接口。应提取公共进度逻辑，为续卷新增目标配置和视图适配器；不能直接复制旧坐标、人物 ID 或归一化范围。

续卷目标使用独立存档键和版本，旧“古城烟火”记录保留。自由游览继续开放，收集成为可选玩法。图像提示可选局部物件剪影或一小块周围环境；这是本项目方案，需单独测试是否泄露答案。

### F. 自动游览中的停留与发现——沿用刚加入的播放功能

提供可选“慢逛”节奏：空旷田野平稳前进，到茶摊或仓场留出短暂停顿，让用户有时间注意动作。点击人物或物件仍暂停镜头，用户主动继续后再走。

不要让每个互动都弹窗、强制移动镜头或自动计入收藏。停留点不是发现记录；实际尝试和发现继续由用户完成。此项是结合本项目自动游览的新设计，并非声称 Hidden Folks 使用同样导览。

## 4. 最小技术结构

建议在续卷上增加一个独立交互层，保持现有坐标、人物与底图体系：

```text
对象配置：id / bounds / depth / pivot / sprite / hitMask
行为组件：toggle / rotate / slide / timeline / reveal / sound
运行状态：idle / active / recovering / completed
事件连接：rope.progress → cargo.height → porter.receive
```

这些是建议的配置字段，当前仓库尚无对应新增模块。

关键接入点：

1. **输入归属**：按下时先判断是否命中可操作道具。命中吊绳后由它接管拖动；否则沿用画卷平移。双指缩放可取消物件操作。保留现有单击与拖动区分。
2. **世界坐标**：复用 `worldPoint()`，旋转或滑动道具的命中要换算到道具局部坐标，不能只用静态矩形。
3. **绘制与遮挡**：建议按“干净底图 → 后层物件/人物 → 前层门帘/栏杆 → 提示”绘制；实际命中也遵循相同前后关系，挡住的目标不能穿透点到。
4. **形变命中**：目前人物使用原图透明度结合位置与翻转命中，没有精确反算网格形变。若动作明显增大，需跟随当前姿势更新命中或提供保守容差。
5. **缓存失效**：动态物件从静态背景缓存中拆出，画卷定位、对象状态和缩放变化要分别处理。沿用可见人物绘制和已有 48 MiB 形变缓存上限。
6. **生命周期**：离屏物件可保存状态并暂停绘制；背景页暂停更新。是否按时间补算动作要事先规定，避免返回时跳变。

## 5. 推荐制作顺序

| 批次 | 具体交付 | 通过标准 |
| --- | --- | --- |
| 第一批：一个街区样板 | 仓场吊绳、一次搬货回应、客舍布帘的素材样板 | 操作结果可见；拖物件不拖画卷；没有底图残影；可恢复初始状态 |
| 第二批：复用与声音 | 将样板组件配置化，增加田畴/街市/仓场音景 | 位置变化过渡平滑；点击音清楚；静音与后台暂停可靠 |
| 第三批：可选寻找 | 七区各一至两个目标、线索与收藏 | 刷新不丢进度；不重复计数；打开遮挡物后才能命中隐藏目标 |
| 第四批：导览节奏 | 自动游览的可选停留点 | 用户可随时打断；继续时不跳回起点；不替用户完成寻找 |

第一批先围绕一个完整故事集中制作，不同时给全卷所有人物加新动作。仓场最适合验证“用户操作—机关变化—人物接续”，客舍布帘最适合验证“遮挡—揭示—发现”。

## 6. 验证与边界

- 桌面、手机竖屏、手机横屏均检查点击、拖动、双指缩放及面板遮挡。
- 连续快速点击、反向拖动、视图跳转、隐藏页面和加载失败都能回到可理解的状态。 
- 机关运行时人物不穿插，遮挡层与可点击层一致。
- 新增素材按视野附近加载；沿用 Canvas 的可见性筛选，并在实际目标设备上采样。此处没有实测新增功能的帧率。
- 需要减少动态效果时，允许切换到明确的终态或极短过渡，并通过文字反馈操作结果。
- 不建议把整卷变成统一循环抖动，不为场景互动强制引入 Unity，也不把黑白配色作为必要前提。

调研后的首批原位样板已于 2026-10-15 接入续卷：仓场吊绳联动、客舍开帘与人物主动回应，见 [构建与验证说明](STREET-WORKSHOP.md)。分区声音、续卷收藏和导览停留仍为后续建议。
